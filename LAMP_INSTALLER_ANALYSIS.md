### Key Observations

- **`ndxzsite/config/config.php`** does not exist in the repo—it is generated by the installer. Its absence is how the system detects an uninstalled state (`index.php` line 10, `install.php` lines 81, 165, 205).
- **`htaccess`** must be renamed to **`.htaccess`** and placed in the web root.
- Four directories require **write permissions**: 
  - `files/`
  - `files/gimgs/`
  - `files/dimgs/`
  - `ndxzsite/config/`
  - (Reference: `install.php` lines 105–143)

## 2. Current Installation / Setup Documentation

There is **no install guide** beyond `README.md` (8 lines, just a trademark notice). The installation is a **browser-based 5-step wizard** at `ndxzstudio/install.php`.

### Wizard Flow (`install.php` lines 42–64)

- **Page 0**: Language selection; PHP ≥ 5.6.0 check (line 79).
- **Page 1**: Directory permission check (lines 98–156) — verifies `files/`, `files/gimgs/`, `files/dimgs/`, `ndxzsite/config/` are writable.
- **Page 2**: DB credentials form (lines 158–251) — collects host, db name, user, password, table prefix (default `ndxzbt_`). Also handles migration from older `ndxz-studio/` path.
- **Page 3**: Optionally imports data from prior install (`ndxz-studio/`) or redirects to preferences login.
- **Page 4**: Error state for unresolvable problems.

The installer calls `do_installation()` which runs `writeConfig()` then `install_db()`.

## 3. Database Requirements and Schema

- **Engine**: MySQL/MariaDB via `mysqli_*` functions (`db.mysql.php` lines 43, 47, 62, 74).
- **Charset**: UTF-8, `utf8_unicode_ci` collation (`install.php` lines 23–24).
- **SQL mode**: `SET SESSION sql_mode = 'ANSI'` (`db.mysql.php` lines 80–83) — required for MySQL 5.6+.
- **Table engine**: MyISAM (`install.php` line 339).
- **Default table prefix**: `ndxzbt_` (set in installer form, stored in `config.php` as `PX` constant).

## 4. PHP Version and Dependency Requirements

### Minimum PHP

**PHP 5.6.0** or higher (`install.php` line 79: `version_compare(PHP_VERSION, '5.6.0', '>=')`).

PHP 7.x and 8.x are compatible. The codebase uses `#[AllowDynamicProperties]` attribute (PHP 8.2+ compatibility noted).

### Required PHP Extensions

- **`mysqli`** — mandatory; entire DB layer uses `mysqli_*` functions (`db.mysql.php` lines 43, 47, 62, 74, etc.)
- **`gd` or `imagick`** — image resizing; detected dynamically: `(extension_loaded('imagick')) ? 'media_imagick' : 'media_gd'` (`defaults.php` line 72). **GD is the fallback**.
- **`date`** / timezone functions (`install.php` lines 11–13; `common.php` line 3)
- **File I/O**: `fopen`, `fwrite`, `fread` for config file writing and template reading

### No External Dependencies

- No Composer, no npm, no external package manager — the codebase is entirely self-contained.

## 5. Configuration Files and Environment Setup

### `ndxzsite/config/config.php` (Generated by Installer)

This file is generated by installer via `writeConfig()` (lines 734–770):

```php
$indx['db']   = 'databasename';
$indx['user'] = 'username';
$indx['pass'] = 'password';
$indx['host'] = 'localhost';
$indx['sql']  = 'mysql';
if (!defined('PX')) { define('PX', 'ndxzbt_'); }
```

The template is `ndxzsite/config/config.example.php`.

### `ndxzsite/config/options.php` (Static)

Shipped with repo; contains:

- `MODREWRITE` constant (default `false`, line 5) — set to `true` if Apache `mod_rewrite` is enabled
- Image quality, max upload size, cache settings, language default

### `htaccess` → `.htaccess`

Must be copied/renamed to `.htaccess` in web root. Contents:

```
RewriteEngine on 
RewriteCond %{REQUEST_FILENAME} -f [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^(.+) - [PT,L]
RewriteRule ^(.+) index.php
```

Requires `AllowOverride All` in Apache virtualhost config. If `mod_rewrite` is unavailable, set `MODREWRITE` to `false` in `options.php` and URLs will be prefixed with `/index.php`.

### URL Construction

**`defaults.php` lines 31–40**: `BASEURL` is built from `$_SERVER['SERVER_NAME']` and `$_SERVER['SERVER_PORT']`; no hardcoded domain.

## 8. Installer Implementation Recommendations

### Key Considerations for a LAMP Installer Script

1. **Pre-Installation Checks**:
   - Verify PHP version ≥ 5.6
   - Check required PHP extensions: `mysqli`, `gd` or `imagick`
   - Confirm Apache `mod_rewrite` is enabled
   - Test write permissions on `files/`, `files/gimgs/`, `files/dimgs/`, `ndxzsite/config/`

2. **File Deployment**:
   - Extract Indexhibit source to web root
   - Rename `htaccess` to `.htaccess`
   - Set permissions: `777` on `files/*` and `ndxzsite/config/`

3. **Database Setup**:
   - Create MySQL database with UTF-8 charset and `utf8_unicode_ci` collation
   - Create database user with full privileges on that database
   - Set `SET SESSION sql_mode='ANSI'` for MySQL 5.6+

4. **Configuration Generation**:
   - Generate `ndxzsite/config/config.php` with DB credentials
   - Optionally enable `mod_rewrite` in `ndxzsite/config/options.php`

5. **Installer Invocation**:
   - Direct user to `http://yoursite/ndxzstudio/install.php` OR
   - Pre-populate the wizard via URL parameters (if supported)
   - The web wizard handles DB table creation, seed data insertion, and admin user setup

6. **Post-Installation**:
   - Verify `ndxzsite/config/config.php` is created and readable
   - Optionally lock down `ndxzstudio/install.php` or delete it after installation
   - Display login credentials: default admin user is `index1` / `indexhibit` (MD5: `22645ed8b5f5fa4b597d0fe61bed6a96`)

## 9. Potential Automation Opportunities

### For a Shell-Based Installer

1. **Auto-detect server environment** (OS, PHP version, available extensions)
2. **Create MySQL database and user** non-interactively (via `mysql` or `mysqladmin`)
3. **Generate `config.php`** programmatically instead of web wizard
4. **Auto-run the DB schema** (SQL files extracted from `install.php`)
5. **Enable Apache `mod_rewrite`** and set permissions automatically
6. **Display post-install checklist** including default login

### Challenges

- The existing web-based installer (`install.php`) expects a browser; refactoring to CLI would require extracting database setup logic into standalone SQL or CLI scripts.
- Default admin password is hardcoded (MD5 hash of `indexhibit`); a real installer should allow custom password setup.
- No hooks or plugins API for customizing installer behavior.
